具体功能要求：

A. Chat 页面增加模式选择
- 默认模式：普通聊天
- 可选模式：知识库问答
- 默认仍是普通聊天
- 用户必须手动选择“知识库问答”后，才调用 /api/knowledge/query

B. 普通聊天模式
- 行为保持不变
- 仍然调用 /api/chat
- 不展示 citations / hits
- 不受 Knowledge 模式影响

C. 知识库问答模式
- 用户在 Chat 输入框输入问题
- 点击发送或 Enter 发送
- 调用现有 /api/knowledge/query
- 请求参数至少包含：
  - question
  - kb_id
  - top_k
- 可以在 Chat 页面新增 kb_id / top_k 输入项，或用默认值 default / 4
- 返回后在 Chat 消息区展示 answer.text
- 如果 grounded=false，要明确提示“未找到可靠知识片段”
- 如果有 citations，要展示引用来源
- 如果有 hits，可折叠或简要展示命中文件
- 如果模型未启用，显示 KNOWLEDGE_MODEL_DISABLED 错误，不 fallback 到 /chat

D. 状态隔离
- 普通 Chat 历史不要被知识库问答污染，或者至少要明确标识“知识库问答”
- 不要把知识库问答结果写进普通 /chat 上下文
- 不要改变 Chat 历史裁剪逻辑，除非必要
- 不要让 Panel 快速 Chat 自动变成知识库问答

E. Panel
- Panel 可以增加一个“基于知识库提问”的跳转入口，但不要在 Panel 里实现完整知识库问答表单
- 如果改 Panel，只做轻量入口，不改 Panel 快速 Chat 默认行为

F. 文档同步
- 如果代码实现完成，轻量更新 README / VERSION_PLAN / TASKS / ARCHITECTURE
- 写清 V1.9 当前支持：
  - Chat 页面手动知识库问答模式
  - 普通 Chat 默认行为不变
  - 底层复用 /knowledge/query
- 写清仍不支持：
  - /chat 默认自动接入知识库
  - 自动记忆
  - 自动读取文件
  - embedding / ChromaDB
