## 要求

1. 移除开发阶段遗留文字，例如“当前为 V1.6-M2 静态壳层”这类表述。
2. 强化 Panel 第一屏：

   - 知识库状态

4. 文件工具卡不要只写“本轮不在面板内读取文件”这种开发说明。
5. 保持 Panel 是入口层，不在 Panel 内实现完整 Files / Knowledge 表单。
6. Panel 按钮跳转必须保持正常：
   - 后端状态
   - 聊天
   - 文件工具
   - Knowledge
   - Markdown 接入区
7. 不改变 Panel 快速 Chat 默认行为。

# M4：Chat 页面体验优化

## 目标

让普通聊天 / 知识库问答模式更清楚，减少技术感。

## 要求

1. 模式切换区域更清晰：
   - 普通聊天
   - 知识库问答
2. kb_id / top_k 参数可以保留，但展示要更自然。
3. 默认仍为普通聊天。
4. 普通聊天行为不变。
5. 知识库问答仍调用 /api/knowledge/query。
6. 优化知识库问答结果展示：
   - answer.text 清楚展示
   - grounded=false 用中文友好提示
   - citations / hits 不要太复杂
   - 技术字段尽量放到弱化区域
7. KNOWLEDGE_MODEL_DISABLED 等错误要有中文说明。
8. Chat 空状态不要暴露 Echo 这类实现细节。
9. 不要让知识库问答写入普通 chatHistory。
10. 不要改变 Chat 历史裁剪逻辑，除非必须。

# M5：Knowledge 页面信息架构整理

## 目标

Knowledge 页面现在功能太多，需要更清晰的信息结构。

当前包含：

- 知识库状态
- 单篇 Markdown 入库
- Markdown 目录批量入库
- 搜索
- 问答

## 要求

1. 重新整理 Knowledge 区块顺序和视觉层级。
2. 可以使用分组、标题、说明、轻量折叠或二级区域。
3. 明确区分：
   - 接入内容
   - 检索内容
   - 基于知识库问答
   - 状态信息
4. 单篇入库和目录批量入库可以归到“Markdown 接入”组。
5. 搜索和问答必须视觉上更容易区分：
   - 搜索：不调用模型
   - 问答：调用模型
6. 技术字段如 fts_enabled、index_method、chunk_index 等尽量弱化或放在详情中。
7. 不改变实际 API 调用。
8. 不改变单篇入库、目录入库、search、query 的功能逻辑。
9. 不自动入库。
10. 不自动 query。
