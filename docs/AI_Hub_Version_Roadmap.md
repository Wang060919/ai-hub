# AI Hub 最终版本路线图

本文档是 AI Hub 项目的最高优先级版本边界说明，用于约束开发范围、排定迭代顺序，并服务后续 Claude Code、Codex、Gemini 接力开发。

文档优先级：

1. `AI_Hub_Version_Roadmap.md`
2. `AI_Hub_Implementation_Plan.md`
3. `AI_Hub_Project_Planning.md`

总原则：

- 不继续扩展新功能
- 不删除长期愿景
- 远期能力不提前塞进 V0.1
- 8 天冲刺先保住可运行后端闭环

## V0.1 微核心验证版

### 目标

证明 “FastAPI + Skill 插件架构” 成立。

### 内容

- FastAPI 网关
- 标准 JSON 协议
- BaseSkill
- EchoSkill
- TimeSkill
- IdeaCaptureSkill
- SQLite 灵感盲存

### 不包含

- Ollama
- Dify
- OpenClaw
- Docker
- OCR
- Tauri
- Live2D

### 说明

V0.1 的重点不是做出完整 AI 产品，而是交付一个能运行、能路由、能返回、能存储的最小闭环。

## V0.2 学习能力接入版

### 目标

接入已有 Dify 四级助手，形成真实 AI 学习闭环。

### 内容

- DifyEnglishSkill
- Dify API 调用
- 错词记录
- 学习记录
- 错误处理

### 版本原则

- 优先做 Dify 接入
- 不优先做本地 Ollama
- 不把本地模型路由放在本版本最前面

### 说明

V0.2 是第一个真正面向用户价值的 AI 版本，重点在“已有业务能力接入”，而不是“本地模型炫技”。

## V0.3 本地模型路由版

### 目标

从规则路由升级为 AI Router。

### 内容

- Ollama 或 DeepSeek Router
- 意图分类
- 失败回退 RuleRouter
- 想法评估功能

### 说明

本地模型路由必须后置到 V0.3，原因是它依赖前面已经存在的网关、Skill 抽象、数据结构和 Dify 闭环。没有前两版打底，直接做 AI Router 容易把项目带进环境和调优泥潭。

## V0.4 自动化执行版

### 目标

让 AI 安全处理文件和表格。

### 内容

- OpenClaw 接入
- Docker 临时沙盒
- 文件整理
- Excel / CSV 处理
- 操作日志和回滚设计

### 说明

自动化执行是高价值能力，但也带来更高风险，因此要放在微核心、学习闭环、本地路由之后，再建立安全边界和可回滚设计。

## V0.5 多模态感知版

### 目标

形成截图 OCR 输入闭环。

### 内容

- 全局快捷键
- 截图
- OCR
- OCR 文本进入 `/chat`

### 说明

多模态输入会显著扩展交互体验，但不属于当前 8 天冲刺核心。它依赖前面的后端能力足够稳定之后再接入更合理。

## V1.0 桌面客户端版

### 目标

交付桌面端可用产品。

### 内容

- Tauri + Vue3
- 悬浮窗
- 流式输出
- 简单状态展示

### 版本边界

- V1.0 必做项是桌面客户端
- Live2D 不是 V1.0 必做项
- Live2D 只作为可选增强项

### 说明

V1.0 标志着项目从“后端能力验证”进入“可交付产品化”阶段，重点是可安装、可交互、可展示，而不是拟人表现层完整度。

## V1.1 拟人表现增强版

### 内容

- Live2D
- 情绪状态联动
- 桌宠表现层增强

### 说明

Live2D 放到 V1.1 更合理，因为它属于表现层增强，而不是桌面产品成立的前置条件。如果 V1.0 时间富余，也可以作为可选增强项接入，但不能反向绑架 V1.0 进度。

## V1.5 主动感知版

### 内容

- Always-On Copilot
- 心流守卫
- 通信分拣

### 说明

该版本只作为远期规划，不进入当前 8 天冲刺，也不进入前几个基础版本的必做清单。

## V3.0 赛博管家愿景版

### 内容

- Home Assistant
- IoT 联动
- 物理世界控制

### 说明

这是 AI Hub 的终极愿景，用于保留项目未来的想象空间与架构延展方向，不参与当前阶段排期。

## 当前结论

当前 8 天冲刺应严格聚焦以下顺序：

1. V0.1 微核心验证版
2. V0.2 学习能力接入版
3. 文档、测试与交接补齐

以下内容全部不进入当前冲刺核心范围：

- 本地模型路由
- OpenClaw
- Docker 沙盒
- OCR
- Tauri
- Live2D
- ChromaDB
- GraphRAG
- Always-On
- IoT

如果后续开发出现范围膨胀，应以本路线图为准进行裁剪。
