# AI Hub 技术决策记录

本文档记录当前已经确认的技术决策，用于约束 8 天冲刺和后续 Gemini 接管时的实现边界。

## D-001 当前先做 V0.1

- 决策：当前开发优先完成 `V0.1 微核心验证版`。
- 原因：8 天冲刺必须先交付可运行后端闭环，证明核心架构成立。
- 影响：所有开发工作优先服务 FastAPI 微核心、`/chat`、Skill 抽象和 SQLite 灵感盲存。

## D-002 V0.1 不接 Ollama

- 决策：`V0.1` 不接入 Ollama 或其他本地模型运行时。
- 原因：本地模型部署、显存与环境调优成本高，会拖慢当前冲刺节奏。
- 影响：V0.1 只允许规则路由，不做 AI Router。

## D-003 V0.1 不做前端

- 决策：`V0.1` 不开发前端页面或桌面端界面。
- 原因：当前目标是先跑通后端闭环，而不是产品表现层。
- 影响：优先使用命令行、API 或后续测试工具验证能力。

## D-004 V0.1 只用 FastAPI + SQLite

- 决策：`V0.1` 技术栈收敛为 `FastAPI + SQLite`。
- 原因：依赖少、实现快、便于验证最小闭环。
- 影响：当前阶段不引入向量数据库、容器体系或复杂基础设施。

## D-005 V0.2 优先接 Dify

- 决策：`V0.2` 优先接入 Dify 四级英语助手。
- 原因：Dify 已具备现成业务价值，更适合在短周期内形成可展示成果。
- 影响：V0.2 的 AI 能力重点是 DifyEnglishSkill，而不是本地模型。

## D-006 本地模型路由放到 V0.3

- 决策：本地模型路由延后到 `V0.3`。
- 原因：必须先有稳定网关、Skill 抽象和 Dify 闭环，再考虑 AI Router。
- 影响：当前阶段不得提前实现 Ollama Router、DeepSeek Router 或意图分类系统。

## D-007 OpenClaw + Docker 放到 V0.4 或更后

- 决策：OpenClaw 与 Docker 沙盒能力放到 `V0.4` 或更后。
- 原因：自动化执行能力风险更高，必须放在基础能力稳定之后。
- 影响：当前阶段不得创建自动化执行子系统或容器执行链路。

## D-008 OCR 放到 V0.5

- 决策：OCR 能力延后到 `V0.5`。
- 原因：多模态输入不属于当前 8 天冲刺核心闭环。
- 影响：当前阶段不得实现截图、OCR、全局快捷键等能力。

## D-009 Tauri 放到 V1.0

- 决策：Tauri 桌面端放到 `V1.0`。
- 原因：桌面客户端属于产品化阶段，不属于当前后端验证阶段。
- 影响：当前阶段不得创建桌面端目录、页面或相关工程。

## D-010 Live2D 放到 V1.1 或 V1.0 可选项

- 决策：Live2D 放到 `V1.1`，或仅作为 `V1.0` 可选增强项。
- 原因：Live2D 属于表现层增强，不是桌面产品成立的前置条件。
- 影响：当前阶段不得提前接入桌宠、情绪状态联动或拟人表现层实现。

## 使用规则

- 新决策必须编号追加，不覆盖已有决策
- 若与 `AGENTS.md` 或三份核心文档冲突，以它们为准
- 实现前先检查本文件，避免重复讨论已经定稿的范围边界
