# AI Hub 8 天冲刺实施规划书

## 1. 实施原则

本轮开发只服务于 8 天冲刺，不继续扩展新功能，优先建立一个可运行、可交接、可继续迭代的后端闭环。

实施原则如下：

- 先跑通后端闭环
- 先规则路由，后 AI 路由
- 先 Dify，后 Ollama
- 先 SQLite，后 ChromaDB
- 先命令行 / API，后桌面 UI

补充说明：

- 当前阶段优先验证网关、路由、Skill 抽象和数据沉淀
- 所有远期能力只做文档设计，不在 8 天内强行实现
- 文档必须能让 Claude Code、Codex、Gemini 直接接力开发

## 2. 第 0 阶段：项目规则与文档

这一阶段的目标不是写功能，而是统一协作约束与交接入口，避免后面多人接力时反复返工。

优先准备：

- `AGENTS.md`
- `GEMINI.md`
- `README.md`
- `docs/TASKS.md`
- `docs/DECISIONS.md`

这一阶段应明确的内容：

- 项目目标与阶段边界
- 目录约定
- 代码生成与协作规则
- 当前任务清单
- 已确认的架构决策
- 后续接管提示词或说明

## 3. 第 1 阶段：V0.1 FastAPI 微核心

这一阶段是整个 8 天冲刺的核心，目标是交付最小可运行版本。

### 3.1 目标

证明 “FastAPI 微核心 + Skill 插件化网关” 架构成立。

### 3.2 关键文件

- `backend/main.py`
- `backend/schemas.py`
- `backend/router.py`
- `backend/skills/base.py`

### 3.3 必做内容

- 定义统一请求与响应结构
- 实现 Skill 基类 `BaseSkill`
- 实现 `EchoSkill`
- 实现 `TimeSkill`
- 提供 `POST /chat`
- 完成最基础规则路由

### 3.4 本阶段要求

- `/chat` 能稳定返回结果
- 返回格式统一为 JSON
- 路由逻辑保持简单可读
- 不在此阶段引入本地模型路由

## 4. 第 2 阶段：SQLite 灵感盲存

这一阶段在 V0.1 微核心上补齐第一个真实业务能力。

### 4.1 目标

让 AI Hub 不只是“会回复”，还具备最基础的数据沉淀能力。

### 4.2 必做内容

- 实现 `IdeaCaptureSkill`
- 建立 `ideas` 表
- 支持记录想法
- 支持查询最近想法

### 4.3 ideas 表字段

- `id`
- `content`
- `status`
- `created_at`
- `updated_at`

### 4.4 范围约束

- 当前只做 SQLite
- 当前不接 ChromaDB
- 当前不做想法自动评估
- 当前优先保证写入稳定、查询清晰、结构简单

## 5. 第 3 阶段：V0.2 Dify 四级助手接入

这一阶段是 8 天冲刺里唯一优先接入的真实 AI 能力。

### 5.1 目标

接入已有 Dify 四级英语助手，形成真实 AI 学习闭环。

### 5.2 必做内容

- 实现 `DifyEnglishSkill`
- 使用环境变量 `DIFY_API_URL`
- 使用环境变量 `DIFY_API_KEY`
- 支持查词
- 支持出题
- 支持判题
- 支持错词整理

### 5.3 实施要求

- API Key 不写死在代码中
- 必须有基础错误处理
- 请求失败时返回可理解的错误信息
- Skill 接口风格应与已有 Skill 保持一致

### 5.4 优先级说明

本阶段优先级高于本地 Ollama 接入。

原因是：

- Dify 已有现成业务价值
- 接入成本低于本地模型部署
- 更适合在 8 天内形成可展示成果

## 6. 第 4 阶段：文档、测试与交接

当前阶段不需要追求完整工程化，但必须满足最基本的可运行、可说明、可接手。

### 6.1 必做内容

- `README` 运行说明
- `.env.example`
- 基础测试命令
- Gemini 接管提示词

### 6.2 至少要说明清楚的内容

- 如何安装依赖
- 如何启动服务
- 如何配置环境变量
- 如何调用 `/chat`
- 如何验证 Echo / Time / Idea / Dify

### 6.3 交接目标

做到别人拿到仓库后，可以在较短时间内：

- 理解项目当前阶段
- 跑起服务
- 验证核心接口
- 继续向后开发

## 7. 后续阶段只做设计，不在 8 天内强行实现

以下内容全部作为后续阶段设计保留，不在本轮冲刺里强行落地：

- 本地模型路由
- OpenClaw + Docker
- OCR
- Tauri
- Live2D

进一步说明：

- 本地模型路由延后到 V0.3
- OpenClaw + Docker 延后到 V0.4 或更后
- OCR 延后到 V0.5
- Tauri 延后到 V1.0
- Live2D 延后到 V1.1，或作为 V1.0 可选项

## 8. 验收标准

8 天冲刺结束时，至少满足以下标准：

- 项目能运行
- `/chat` 能返回 Echo / Time / Idea / Dify 结果
- SQLite 能写入
- `README` 能指导他人跑起来

如果时间不足，取舍顺序必须明确：

1. 先保住 V0.1
2. 再完成 Dify 接入
3. 最后补文档、测试与交接材料

## 9. 与版本路线图的关系

本文件用于定义 8 天内的实施顺序，但不单独决定版本优先级。

开发时必须遵守以下文档优先级：

1. `AI_Hub_Version_Roadmap.md`
2. `AI_Hub_Implementation_Plan.md`
3. `AI_Hub_Project_Planning.md`

如果出现愿景过大、任务扩散、阶段边界模糊等情况，应优先回看版本路线图，避免把远期能力提前塞进当前冲刺。
